# Workflow 43: Developer Experience

**Duration**: 4-20h | **Outputs**: DX assessment, improvement roadmap, tooling recommendations, satisfaction metrics

## Trigger

- Developer experience improvement initiative, DX assessment
- Tooling optimization, onboarding improvement
- Developer productivity measurement, satisfaction survey
- Remote developer experience, IDE optimization

## Steps

### Step 1: DX Assessment
Measure current developer satisfaction. Identify friction points. Map developer journey. Benchmark against industry.
**Time**: 2-4h. **Edge Cases**: Survey fatigue → keep short; honest feedback → anonymous; cultural differences → adapt surveys.

### Step 2: Tooling Audit
Inventory development tools. Assess tool integration. Identify gaps. Plan tool consolidation.
**Time**: 2-4h. **Edge Cases**: Shadow IT → include all tools; licensing → cost analysis; compatibility → integration assessment.

### Step 3: Environment Optimization
Optimize local development. Improve build times. Streamline setup. Plan remote development.
**Time**: 4-8h. **Edge Cases**: Multiple OS → cross-platform; slow builds → caching; complex setup → automation.

### Step 4: Onboarding Improvement
Design onboarding program. Create documentation. Implement buddy system. Measure time to first commit.
**Time**: 2-4h. **Edge Cases**: Remote onboarding → virtual; senior vs junior → tiered; domain complexity → guided tours.

### Step 5: Feedback and Iteration
Establish feedback channels. Implement NPS tracking. Create improvement backlog. Plan regular assessments.
**Time**: 1-2h. **Edge Cases**: Survey fatigue → pulse surveys; action visibility → close the loop; benchmarking → industry comparison.

### Step 6: Metrics and Reporting
Define DX metrics. Create dashboards. Track improvements. Report to leadership.
**Time**: 1-2h. **Edge Cases**: Qualitative vs quantitative → both; leading vs lagging → mix; attribution → control groups.

## Quality Gates

| Gate | Criteria |
|------|----------|
| QG1 | DX baseline established |
| QG2 | Tooling audit complete |
| QG3 | Environment optimized |
| QG4 | Onboarding improved |
| QG5 | Feedback channels active |
| QG6 | Metrics tracked |

## Anti-Patterns

1. **Tool-first approach** — Buying tools without understanding needs
2. **One-size-fits-all** — Same setup for all developers
3. **Ignoring feedback** — Not acting on developer input
4. **No measurement** — Can't prove improvement

## Edge Cases

- Remote developers → Cloud development environments
- Multiple IDEs → Flexible tooling
- Security constraints → Compliant tooling
- Contractors → Temporary access patterns
